macOS 应用以 `.app` 包的形式分发。别看它带着 `.app` 扩展名，这其实是一个结构固定的目录，macOS 把它当作单个可启动的应用来对待。包里装着编译好的可执行文件、图标图片等资源，以及告诉 macOS 如何运行和展示你应用的元数据。要让 .NET 和 Avalonia 项目在 `.app` 包里跑起来，发布之后还得做一些额外工作。

:::tip[用 Parcel 让打包更省事]
[Parcel](/tools/parcel/packaging-for-macos) 能为 Avalonia 应用自动完成 macOS 打包：一条命令就把包结构、`Info.plist` 生成、代码签名、公证和 DMG 制作全办了。Parcel 还能在 Windows 和 Linux 上制作 macOS 包。如果你不想折腾下面这些手动步骤，上手请看 [Parcel 配置指南](/tools/parcel/setup)。
:::

## 手动打包 {#manual-packaging}

本文余下部分讲的是如何手动创建、签名、公证并分发 `.app` 包。

Avalonia 的 `.app` 包具有下面这样的结构：

<FileTree data={[
  {
    name: 'MyProgram.app',
    type: 'folder',
    children: [
      {
        name: 'Contents',
        type: 'folder',
        children: [
          {
            name: '_CodeSignature',
            type: 'folder',
            comment: 'stores code signing information',
            children: [
              { name: 'CodeResources', type: 'file' }
            ]
          },
          {
            name: 'MacOS',
            type: 'folder',
            comment: 'all your DLL files, etc. -- the output of dotnet publish',
            children: [
              { name: 'MyProgram', type: 'file' },
              { name: 'MyProgram.dll', type: 'file' },
              { name: 'Avalonia.dll', type: 'file' }
            ]
          },
          {
            name: 'Resources',
            type: 'folder',
            children: [
              { name: 'MyProgramIcon.icns', type: 'file', comment: 'icon file' }
            ]

        ]
      }
    ]
  }

`Info.plist` 文件是一份 XML 属性列表，充当这个包的清单：它声明应用的标识、版本、图标、可执行文件名等元数据，macOS 启动时会读取它。每个 `.app` 包都必须有一份。

### 制作应用包 {#making-the-application-bundle}

创建 `.app` 这套文件/目录结构有好几种办法。在哪个操作系统上做都行，因为 `.app` 不过是一组按特定格式摆放的目录，相关工具也不挑系统。不过，如果你在 WSL 之外的 Windows 上构建，可执行文件可能缺少在 macOS 上执行所需的属性，这时需要在一台 Unix 机器上对发布出来的二进制跑一遍 `chmod +x`。这个二进制最终位于 `MyApp.app/Contents/MacOS/` 目录中，其名称应与 `CFBundleExecutable` 一致。

`.app` 结构能否成立，取决于 `Info.plist` 文件格式是否规范、内容是否正确。建议用 Xcode 来编辑 `Info.plist`，它对所有属性都有自动补全。下列键是必需的：

| 按键 | 说明 | 示例 |
|---|---|---|
| `CFBundleExecutable` | 必须与 `dotnet publish` 中的二进制名一致（即去掉 `.dll` 的程序集名）。 | `MyApp` |
| `CFBundleName` | 应用的显示名称（最多 15 个字符）。 | `My App` |
| `CFBundleDisplayName` | 完整显示名称。仅当 `CFBundleName` 超过 15 个字符时才需要。 | `My Application` |
| `CFBundleIconFile` | 你的 `.icns` 图标文件名，含扩展名。 | `MyApp.icns` |
| `CFBundleIdentifier` | 反向 DNS 格式的唯一标识。 | `com.myapp.macos` |
| `NSHighResolutionCapable` | 启用 Retina 显示支持，设为 `<true/>`。 | `true` |
| `CFBundleVersion` | 内部构建版本号。 | `1.4.2` |
| `CFBundleShortVersionString` | 对用户显示的版本字符串。 | `1.4.2` |

若你需要注册自定义 URL 方案或文件类型关联，请参阅 [macOS 平台集成指南](/docs/platform-specific-guides/macos)。

`Info.plist` 全部键的完整清单，请看苹果的 [Information Property List](https://developer.apple.com/documentation/bundleresources/information-property-list) 参考。

如果工具链在某一步报错说你的 assets 文件没有针对 `osx-64` 的目标，请把下列[运行时标识](https://docs.microsoft.com/en-us/dotnet/core/rid-catalog)加进 `.csproj` 顶部的 `<PropertyGroup>` 中：

```xml
<RuntimeIdentifiers>osx-x64</RuntimeIdentifiers>
```

按需添加其他运行时标识，彼此之间用分号 \(;\) 分隔。

#### 关于 `.app` 可执行文件 {#about-the-app-executable-file}

启动你的 `.app` 包时，macOS 真正执行的那个文件**不带**常见的 `.dll` 扩展名。如果要放进 `.app` 包的发布目录里没有同时出现 `MyApp` \(可执行文件\) 和 `MyApp.dll`，那多半是哪里没生成对，macOS 也多半没法正常启动你的 `.app`。

[.NET Core 在 macOS 上的分发和公证方式近来有所变动](https://docs.microsoft.com/en-us/dotnet/core/install/macos-notarization-issues)，导致 `MyApp` 可执行文件（在上述文档中又称 "app host"）不再生成。**你的 `.app` 要正常工作，就必须生成这个文件。**要确保它被生成，请采取下面任一做法：

* 在 `.csproj` 文件中加上这段：

```xml
<PropertyGroup>
  <UseAppHost>true</UseAppHost>
</PropertyGroup>
```

* 在 `dotnet publish` 命令中加上 `-p:UseAppHost=true`。

此外，你或许还想给 dotnet 命令加上 '-p:PublishSingleFile=true'，把大部分 DLL 编进单个应用里，这能让签名和公证省心不少。 

### Manual

首先，发布你的应用 \([dotnet publish 文档](https://docs.microsoft.com/en-us/dotnet/core/tools/dotnet-publish)\)：

```bash
dotnet publish -r osx-x64 --configuration Release -p:UseAppHost=true
```

创建 `Info.plist` 文件，按需增删或修改其中的键：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>CFBundleIconFile</key>
    <string>myicon-logo.icns</string>
    <key>CFBundleIdentifier</key>
    <string>com.identifier</string>
    <key>CFBundleName</key>
    <string>MyApp</string>
    <key>CFBundleVersion</key>
    <string>1.0.0</string>
    <key>LSMinimumSystemVersion</key>
    <string>10.12</string>
    <key>CFBundleExecutable</key>
    <string>MyApp.Avalonia</string>
    <key>CFBundleInfoDictionaryVersion</key>
    <string>6.0</string>
    <key>CFBundlePackageType</key>
    <string>APPL</string>
    <key>CFBundleShortVersionString</key>
    <string>1.0</string>
    <key>NSHighResolutionCapable</key>
    <true/>
</dict>
</plist>
```

然后就可以照本文开头所述搭出 `.app` 的目录结构了。若想用脚本一键完成，可以参考下面这段（macOS/Unix）：

```bash
#!/bin/bash
APP_NAME="/path/to/your/output/MyApp.app"
PUBLISH_OUTPUT_DIRECTORY="/path/to/your/publish/output/net10.0/osx-x64/publish/."
# PUBLISH_OUTPUT_DIRECTORY should point to the output directory of your dotnet publish command.
# One example is /path/to/your/csproj/bin/Release/net10.0/osx-x64/publish/.
# If you want to change output directories, add `--output /my/directory/path` to your `dotnet publish` command.
INFO_PLIST="/path/to/your/Info.plist"
ICON_FILE="/path/to/your/myapp-logo.icns"

if [ -d "$APP_NAME" ]
then
    rm -rf "$APP_NAME"
fi

mkdir "$APP_NAME"

mkdir "$APP_NAME/Contents"
mkdir "$APP_NAME/Contents/MacOS"
mkdir "$APP_NAME/Contents/Resources"

cp "$INFO_PLIST" "$APP_NAME/Contents/Info.plist"
cp "$ICON_FILE" "$APP_NAME/Contents/Resources/$ICON_FILE"
cp -a "$PUBLISH_OUTPUT_DIRECTORY" "$APP_NAME/Contents/MacOS"
```

如果 `.app` 是在 Windows 上做的，记得到一台 Unix 机器上跑一遍 `chmod +x MyApp.app/Contents/MacOS/AppName`，否则应用在 macOS 上根本起不来。

### 给应用签名 {#signing-your-app}

`.app` 文件做好之后，你多半想给应用签名，这样才能完成公证、顺利分发给用户，不至于被 Gatekeeper 刁难。自 macOS 10.15 \(Catalina\) 起，在 App Store 之外分发的应用都必须公证；要让公证通过，你还得启用加固运行时（hardened runtime），并对 `.app` 执行 `codesign`。

加固运行时是 macOS 的一项安全策略，限制应用在运行时能做什么。除非你通过 entitlements 显式申请，否则它会拦下代码注入、加载未签名库、访问特定系统资源等行为。苹果要求所有公证应用都启用加固运行时。

这一步需要一台 Mac，好运行 Xcode 自带的 `codesign` 命令行工具。

### 取得 Developer ID 证书 {#obtaining-a-developer-id-certificate}

若你想公证应用并在 Mac App Store 之外分发，登录钥匙串中就必须有一张 Developer ID Application 证书。没有它，`codesign` 无从签起，分发也就无从谈起。

注意 Xcode 默认用的是云端托管的签名证书，配合 .NET 命令行工具用起来比较别扭。按下面的步骤装一张 `codesign` 能直接使用的本地证书。具体怎么装，取决于你在 Apple Developer 账号中的身份。

#### 你就是账号所有者 {#if-you-own-the-account}

1. Open Xcode.
2. 打开 **Xcode → Settings → Accounts**。
3. 若列表中还没有你的 Apple ID，先把它加上。
4. 选中你的团队，点 **Download Manual Profiles**，证书就会下载进你的钥匙串。
5. 要把证书分享给其他开发者，在「钥匙串访问」中找到它，右键选 **导出**，这会生成一个有密码保护的 `.p12` 文件。

#### 你不是账号所有者 {#if-you-do-not-own-the-account}

1. 请账号所有者把 Developer ID Application 证书导出成 `.p12` 文件（见上文）。
2. 打开**钥匙串访问**，选 **文件 → 导入项目**。
3. 选中导出的那个 `.p12` 文件并输入密码。

运行下面的命令确认证书已装好：

```bash
security find-identity -v
```

你应该能看到列出了一个 `Developer ID Application` 身份，名称后面括号里就是它的团队 ID。比如 `Developer ID Application: My Company (ABC123DEF5)` 中，团队 ID 就是 `ABC123DEF5`。公证时会用到它。

### 运行 codesign 并启用加固运行时 {#running-codesign-and-enabling-hardened-runtime}

启用加固运行时和代码签名是同一步完成的。你得给 `.app` 包内 `Contents/MacOS` 目录下的所有东西都签名；文件实在太多，一般都写个脚本来干。要签名，你需要一个 Apple 开发者账号。

公证应用需要 Developer ID 证书，而这要求订阅付费的 Apple 开发者计划。本地安装证书的步骤请参阅[取得 Developer ID 证书](#obtaining-a-developer-id-certificate)。

你还需要装好 Xcode 命令行工具。装了 Xcode 并运行一次即可，或者在命令行执行 `xcode-select --install` 并按提示安装。

首先创建一个 `MyAppEntitlements.entitlements` 文件，启用带[例外项](https://developer.apple.com/documentation/security/hardened_runtime?language=objc)的加固运行时：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.cs.allow-jit</key>
    <true/>
    <key>com.apple.security.automation.apple-events</key>
    <true/>
</dict>
</plist>
```

然后运行这个脚本，代码签名的活儿它全包了：

```bash
#!/bin/bash
APP_NAME="/path/to/your/output/MyApp.app"
ENTITLEMENTS="/path/to/your/MyAppEntitlements.entitlements"
SIGNING_IDENTITY="Developer ID: MyCompanyName" # matches Keychain Access certificate name

find "$APP_NAME/Contents/MacOS/"|while read fname; do
    if [[ -f $fname ]]; then
        echo "[INFO] Signing $fname"
        codesign --force --timestamp --options=runtime --entitlements "$ENTITLEMENTS" --sign "$SIGNING_IDENTITY" "$fname"
    fi
done

echo "[INFO] Signing app file"

codesign --force --timestamp --options=runtime --entitlements "$ENTITLEMENTS" --sign "$SIGNING_IDENTITY" "$APP_NAME"
```

`codesign` 那一行中的 `--options=runtime` 部分，正是为你的应用启用加固运行时的开关。由于 [.NET Core 未必能完全兼容加固运行时](https://github.com/dotnet/runtime/issues/10562#issuecomment-503013071)，建议加上两个例外项：允许使用 JIT 编译的代码，以及允许发送 Apple Events。前者是 Avalonia 应用在加固运行时下跑起来的必要条件；后者则用于消除 `Console.app` 中出现的一个错误。

注意：微软列出了 [.NET Core 所需的另外几项加固运行时例外](https://docs.microsoft.com/en-us/dotnet/core/install/macos-notarization-issues#default-entitlements)。但要跑一个 Avalonia 应用，真正必需的只有 `com.apple.security.cs.allow-jit` 这一项。其余的可能给你的应用带来安全风险，请谨慎使用。

:::caution[别用 `--deep` 标志]
有些教程建议用 `codesign --deep` 一次性给整个包签名。苹果建议不要用 `--deep`，因为它可能让嵌套的二进制签名不正确。正确做法是像上面的脚本那样逐项显式签名：先遍历文件逐个签，最后再签整个包。
:::

应用签完名后，运行下面的命令，若没有任何报错，就说明签名没问题：

```bash
codesign --verify --verbose /path/to/MyApp.app
```

### 为你的软件做公证 {#notarizing-your-software}

公证是一套自动化流程：你把签好名的应用上传到苹果服务器做安全扫描，通过之后苹果会签发一张票据，证明这个软件已查验过无恶意内容。用户下载你的应用时，macOS 会校验这张票据，然后放行启动，不再弹出「来自身份不明的开发者」警告。自 macOS 10.15（Catalina）起，所有在 Mac App Store 之外分发的应用都必须公证。

公证使用 `notarytool` 命令行工具，它随 Xcode 13 及更高版本一同提供。（更早的 `altool --notarize-app` 流程已被苹果停用，不再可用。）

由于苹果要求开发者账号启用多因素认证，`notarytool` 改用你在 [Apple ID 账户页面](https://account.apple.com/account/manage)生成的 App 专用密码来认证。把它作为具名配置一次性存进钥匙串，此后每次运行就不必再传凭据了：

```bash
xcrun notarytool store-credentials "AC_PASSWORD" \
  --apple-id "you@example.com" \
  --team-id "YOURTEAMID" \
  --password "your-app-specific-password"
```

`AC_PASSWORD` 是你自己取的配置名，`--team-id` 是 App Store Connect 里的团队 ID，`--password` 则是你生成的 App 专用密码。

配置存好之后，公证你的应用：

1. 确认你的 `.app` 已正确完成代码签名。
2. 把 `.app` 装进一个 `.zip` 文件。这一步苹果建议用 `ditto`，因为 `zip` 命令可能引发公证问题：`ditto -c -k --sequesterRsrc --keepParent MyApp.app MyApp.zip`
3. 提交这个压缩包并等待结果。`--wait` 标志会自动轮询，公证成功或失败后才返回，所以不必再单独查状态：

   ```bash
   xcrun notarytool submit MyApp.zip --keychain-profile "AC_PASSWORD" --wait
   ```

4. 若提交被拒，用输出中的提交 ID 取回详细日志：`xcrun notarytool log <submission-id> --keychain-profile "AC_PASSWORD"`
5. 成功之后，用 `xcrun stapler staple MyApp.app` 把公证票据装订到应用上。可以运行 `xcrun stapler validate MyApp.app` 来验证。

公证一完成，你的应用就可以分发了。

#### 为 .dmg 分发做公证 {#notarizing-for-dmg-distribution}

如果你以 `.dmg` 形式分发应用，还得对 `.dmg` 本身再做一次公证。

1. 照常把 `.app` 装进 `.zip` 文件完成公证。
2. 把已公证并装订好（`xcrun stapler`）的应用放进 `.dmg` 中。
3. 用同一条 `xcrun notarytool submit` 命令公证你的 `.dmg` 文件，只是这次指向 `.dmg` 文件而不是 `.zip`。
4. 把公证票据装订到 `.dmg` 文件上：`xcrun stapler staple MyApp.dmg`。

### App Store 打包 {#app-store-packaging}

要准备的东西不少：

* 你的应用符合 [App Store 审核指南](https://developer.apple.com/app-store/review/guidelines/)。
* 你的应用符合 [macOS 人机界面指南](https://developer.apple.com/design/human-interface-guidelines)。
* 有 Apple Developer 账号，且你的 Apple ID 已与之关联。
* 你的应用已在 [App Store Connect](https://appstoreconnect.apple.com/apps/) 中注册。
* 已从 App Store 安装 Transporter 应用。
* 已安装最新版 Xcode，并在其中授权了你的 Apple ID。
* 两张证书：`3rd Party Mac Developer Installer` 用于给 `.pkg` 文件签名，`3rd Party Mac Developer Application` 用于给应用包签名。
* App Store 预置描述文件。在 [Apple Developer 预置描述文件页面](https://developer.apple.com/account/resources/profiles/list)为你的应用获取。
* 两份 entitlements：一份用于给 `.app` 签名，另一份用于给应用的辅助程序签名。
* 你的应用内容已[正确打包](https://developer.apple.com/documentation/bundleresources/placing_content_in_a_bundle)。
* 你的应用包已正确签名。
* 你的 `.dylib` 文件中不含 ARM/x64 之外的架构。可以用 `lipo` 命令行工具把它们剔除。
* 你的应用已能在 macOS 沙盒中运行（见下面的沙盒一节）。

### 获取证书 {#getting-certificates}

* 打开 **Xcode → Settings → Accounts → Manage Certificates...**
* 若证书不存在，就新建它们。
* 带密码导出。 
* 打开导出的文件，导入「钥匙串访问」。
* 在钥匙串中你应当能看到这两张证书：`3rd Party Mac Developer Installer` 和 `Apple Distribution`。若证书名字以别的字符串开头，说明你多半建错了类型，重来一次。
* 在钥匙串中展开导入的密钥，双击里面的私钥。
* 切到「访问控制」标签页。
* 若不想每签一个文件就输一次 Mac 账户密码，请选择 `Allow all applications to access this item`。

### 沙盒与应用包 {#sandbox-and-bundle}

App Store 要求应用运行在沙盒中。沙盒是一种安全机制，把你的应用与系统其余部分隔离开：除非你通过 entitlements 显式申请权限，否则它对文件系统、网络、硬件和其他应用的访问都受限。这保护用户免受恶意或有缺陷软件的侵扰。

你的应用必须为这种受限环境做好准备，遇到某个目录或资源访问不了时不能崩溃。

若应用在沙盒中运行时崩溃，试试开启单文件选项再发布。例如：

`dotnet publish src/MyApp.csproj -c Release -f net10.0 -r osx-x64 --self-contained true -p:PublishSingleFile=true`

你的应用内容必须正确打包。macOS 要求特定类型的文件出现在应用包内特定的目录中。

最重要的几条规则： 
* `.dll` 文件在苹果眼中不算代码，因此应放进 `/Resources` 目录，也不需要签名。
* `/MacOS` 文件中只应放可执行的 mach-o，也就是你的应用可执行文件和其他辅助可执行程序。
* 其余所有 mach-o 的 `.dylib` 文件都应放在 `Frameworks/` 目录中。

要满足这条要求，可以从 `MacOS/` 目录建相对符号链接指向 `Resources/` 和 `Frameworks/` 目录。例如：

`ln -s fromFile toFile`

另外，最好把应用访问资源的方式改成直接读取 `Resources/` 目录、不经任何符号链接，因为在沙盒中走符号链接可能遇到 I/O 访问问题。

### 沙盒 entitlements 与签名 {#sandbox-entitlements-and-signing}

entitlements 是一组键值对，用来声明你的应用需要哪些具体能力，比如网络访问、文件系统访问或 JIT 编译。你把它们写在一个 entitlements `.plist` 文件里，macOS 会在运行时据此执法。请只申请应用确实需要的那些。

第一份 entitlements 文件用于给 `.app/Contents/MacOS/` 目录内所有辅助可执行程序签名，大致长这样。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.app-sandbox</key>
    <true/>
    <key>com.apple.security.inherit</key>
    <true/>
</dict>
</plist>
```

第二份用于给应用可执行文件和整个应用包签名，它应当包含应用所需的全部权限。示例如下：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.cs.allow-jit</key>
    <true/>
    <key>com.apple.security.cs.allow-unsigned-executable-memory</key>
    <true/>
    <key>com.apple.security.cs.disable-library-validation</key>
    <true/>
    <key>com.apple.security.cs.allow-dyld-environment-variables</key>
    <true/>
    <key>com.apple.security.app-sandbox</key>
    <true/>
    <key>com.apple.security.temporary-exception.mach-lookup.global-name</key>
    <array>
        <string>com.apple.coreservices.launchservicesd</string>
    </array>
</dict>
</plist>
```

下面是你的应用可能用得上的一些可选权限：

```xml
    <key>com.apple.security.network.client</key>
    <true/>
    <key>com.apple.security.network.server</key>
    <true/>
    <key>com.apple.security.automation.apple-events</key>
    <true/>
    <key>com.apple.security.files.user-selected.read-write</key>
    <true/>
    <key>com.apple.security.files.bookmarks.document-scope</key>
    <true/>
    <key>com.apple.security.application-groups</key>
    <array>
      <string>[Your Team ID].[Your App ID]</string>
    </array>
```

### 打包脚本 {#packaging-script}

这是一份带注释的打包脚本示例。

```bash
#cleanup folders
rm -rf "App/AppName.app/Contents/MacOS/" 
rm -rf "App/AppName.app/Contents/CodeResources" 
rm -rf "App/AppName.app/Contents/_CodeSignature" 
rm -rf "App/AppName.app/Contents/embedded.provisionprofile" 
mkdir -p "App/AppName.app/Contents/Frameworks/"
mkdir -p "App/AppName.app/Contents/MacOS/"

#Build app
dotnet publish ../../ProjectFolder/AppName.csproj -c release -f net10.0 -r osx-x64 --self-contained true -p:PublishSingleFile=true

#Move app
cd ..
cd ..
cp -R -f ProjectFolder/bin/release/net10.0/osx-x64/publish/* "build/osx/App/AppName.app/Contents/MacOS/"
cd "build/osx/"

APP_ENTITLEMENTS="AppEntitlements.entitlements"
APP_SIGNING_IDENTITY="3rd Party Mac Developer Application: [***]"
INSTALLER_SIGNING_IDENTITY="3rd Party Mac Developer Installer: [***]"
APP_NAME="App/AppName.app"

#<here is moving your app resources to Resources folder using relative symlinks>

#<here is moving your .dylib files to Frameworks folder using relative symlinks>

echo "[INFO] Switch provisionprofile to AppStore"
\cp -R -f AppNameAppStore.provisionprofile "App/AppName.app/Contents/embedded.provisionprofile"

echo "[INFO] Fix libuv.dylib architectures"
lipo -remove i386 "App/AppName.app/Contents/Frameworks/libuv.dylib" "App/AppName.app/Contents/Frameworks/libuv.dylib"

find "$APP_NAME/Contents/Frameworks/"|while read fname; do
    if [[ -f $fname ]]; then
        echo "[INFO] Signing $fname"
        codesign --force --sign "$APP_SIGNING_IDENTITY" "$fname"
    fi
done

echo "[INFO] Signing app executable"
codesign --force --entitlements "$APP_ENTITLEMENTS" --sign "$APP_SIGNING_IDENTITY" "App/AppName.app/Contents/MacOS/AppName"

echo "[INFO] Signing app bundle"
codesign --force --entitlements "$APP_ENTITLEMENTS" --sign "$APP_SIGNING_IDENTITY" "$APP_NAME"

echo "[INFO] Creating AppName.pkg"
productbuild --component App/AppName.app /Applications --sign "$INSTALLER_SIGNING_IDENTITY" AppName.pkg
```

### 测试打包结果 {#testing-a-package}

把你的 `.app` 拷进「应用程序」文件夹并启动。能正常启动就说明一切无误；若崩溃，打开 `Console.app` 查看崩溃报告。

### 把包上传到 App Store {#uploading-a-package-to-the-app-store}

打开 Transporter 应用，登录，选中你的 \*.pkg 包，然后等待校验并上传到 App Store Connect。

若报错，先把问题修掉，重新打包，在 Transporter 里移除原文件后再重新选择它。

上传成功后，你就能在 App Store Connect 中看到自己的包了。

### 在 GitHub Actions 工作流中打包 {#packaging-in-github-actions-workflow}

你可以在 CI/CD 流水线里用 `dotnet` 命令构建应用。至于代码签名和公证，还得多做一点功课。

`codesign` 和 `notarytool` 会从构建机的钥匙串中读取证书，以及与公证服务通信所需的凭据：

```bash
# Create a new keychain
security create-keychain -p "${{ secrets.KEYCHAIN_PASSWORD}}" build.keychain
# Set it as the default keychain
security default-keychain -s build.keychain
# Unlock the keychain so it can be used without an authorisation prompt
security unlock-keychain -p "${{ secrets.KEYCHAIN_PASSWORD}}" build.keychain
```

`KEYCHAIN_PASSWORD` 是你专为这个钥匙串生成的密码，可以每次构建都重新生成，也可以固定用同一个。

接着要把签名证书导入钥匙串。由于 GitHub secrets 只支持字符串，证书 `.p12` 文件需要以 base64 编码形式存放。在流水线中再把这串字符解码成文件并加进钥匙串：

```bash
# Decode certificate to file
echo "${{ secrets.MACOS_CERTIFICATE }}" | base64 --decode > certificate.p12
# Import into keychain
security import certificate.p12 -k build.keychain -P "${{ secrets.MACOS_CERTIFICATE_PWD}}" -T /usr/bin/codesign
```

`MACOS_CERTIFICATE` 是 base64 编码后的 `.p12` 文件，`MACOS_CERTIFICATE_PWD` 是该 `.p12` 文件的密码。

为避免代码签名过程中弹出授权提示框，请让钥匙串放行 `codesign` 的访问：

```bash
# Allow codesign to access keychain
security set-key-partition-list -S apple-tool:,apple:,codesign: -s -k "${{ secrets.KEYCHAIN_PASSWORD}}" build.keychain
```

由于苹果要求开发者账号启用多因素认证（MFA），`notarytool` 改用一个专门的 App 专用密码，可在 Apple 开发者网站上生成。把这个密码添加给 `notarytool`，后面就能直接用了：

```bash
xcrun notarytool store-credentials "AC_PASSWORD" --apple-id "${{ secrets.APPLE_ID }}" --team-id ${{ env.TEAM_ID }} --password "${{ secrets.NOTARY_TOOL_PASSWORD }}"
```

`TEAM_ID` 是 App Store Connect 中的团队 ID，`APPLE_ID` 是你 Apple 账号的邮箱地址，`NOTARY_TOOL_PASSWORD` 则是你生成的 App 专用密码。

要在 GitHub Actions 工作流中用上这几步，把它们作为一个步骤加进构建应用的那个作业里：

```yaml
jobs:
  build_osx:
    runs-on: macos-latest
    env:
      TEAM_ID: MY_TEAM_ID
    steps:
    - name: Setup Keychain
      run: |
        security create-keychain -p "${{ secrets.KEYCHAIN_PASSWORD}}" build.keychain
        security default-keychain -s build.keychain
        security unlock-keychain -p "${{ secrets.KEYCHAIN_PASSWORD}}" build.keychain
        echo "${{ secrets.MACOS_CERTIFICATE }}" | base64 --decode > certificate.p12
        security import certificate.p12 -k build.keychain -P "${{ secrets.MACOS_CERTIFICATE_PWD}}" -T /usr/bin/codesign
        security set-key-partition-list -S apple-tool:,apple:,codesign: -s -k "${{ secrets.KEYCHAIN_PASSWORD}}" build.keychain
        xcrun notarytool store-credentials "AC_PASSWORD" --apple-id "${{ secrets.APPLE_ID }}" --team-id ${{ env.TEAM_ID }} --password "${{ secrets.NOTARY_TOOL_PASSWORD }}"
```

这样配置之后，你就不必再为 `codesign` 或 `notarytool` 指定具体的钥匙串文件了。

接下来是发布应用并签名。
先给这个作业加上这个环境变量：

```yaml
    env:
      SIGNING_IDENTITY: thumbprint_of_certificate_added_to_keychain
```

然后加上这几步：

```yaml
    - name: Publish app
      run: dotnet publish -c Release -r osx-x64 -o $RUNNER_TEMP/MyApp.app/Contents/MacOS MyApp.csproj
    - name: Codesign app
      run: |
        find "$RUNNER_TEMP/MyApp.app/Contents/MacOS/"|while read fname; do
          if [ -f "$fname" ]
          then
              echo "[INFO] Signing $fname"
              codesign --force --timestamp --options=runtime --entitlements MyApp.entitlements --sign "${{ env.$SIGNING_IDENTITY }}" "$fname"
          fi
        done
        codesign --force --timestamp --options=runtime --entitlements MyApp.entitlements --sign "${{ env.SIGNING_IDENTITY }}" "$RUNNER_TEMP/MyApp.app"
```

> **注意：**`RUNNER_TEMP` 是 GitHub Actions 提供的环境变量

代码签名完成后，再往作业里加上这一步，就能给应用包做公证了：

```yaml
    - name: Notarise app
      run: |
        ditto -c -k --sequesterRsrc --keepParent "$RUNNER_TEMP/MyApp.app" "$RUNNER_TEMP/MyApp.zip"
        xcrun notarytool submit "$RUNNER_TEMP/MyApp.zip" --wait --keychain-profile "AC_PASSWORD"
        xcrun stapler staple "$RUNNER_TEMP/MyApp.app"
```

跑完这套工作流，你就得到一个已签名、已公证的应用包，可以打进磁盘映像或安装器了。

要验证代码签名是否生效，得先把它下载下来，以触发 macOS 的隔离机制。办法可以是把它邮件发给自己，或者用 WeTransfer 之类的服务中转一下。

下载好应用包、准备启动时，你应该会看到 macOS 弹窗提示：该应用已扫描，未发现恶意软件。
