## 前置条件 {#prerequisites}

添加移动端或浏览器目标之前，请先确认你的项目已经能以 XPF 跑在桌面上，且 XPF SDK 配置无误。若还没做到，请见[快速上手](/xpf/getting-started)。

:::tip
[CalculatorDemo 仓库](https://github.com/AvaloniaUIOU/CalculatorDemo)中有一个在所有平台上都能跑的 XPF 示例。需要访问权限的话，请找支持团队。
:::

你还得为每个目标平台把开发机准备好。这些步骤与所有 .NET 移动端和浏览器项目都是共通的：

- [搭建 Android 开发环境](/docs/platform-specific-guides/android)
- [搭建 iOS 开发环境](/docs/platform-specific-guides/ios)
- [搭建浏览器开发环境](/docs/platform-specific-guides/webassembly)

## Multi-targeting

.NET 中的移动端和浏览器支持靠的是各平台的工作负载与目标框架。桌面应用通常用 `net8.0` 或 `net8.0-windows`，借助 XPF SDK 的兼容层，它们在 Linux 和 macOS 上同样管用。

要支持 Android、iOS 或浏览器，项目得加上相应的目标框架：`net8.0-android`、`net8.0-ios` 和 `net8.0-browser`。

若你熟悉 Avalonia 的跨平台模板，大概知道 Avalonia 建议为每个目标各建一个项目。但对 XPF 项目而言，**不推荐**这么做：WPF 的嵌入式资源机制假定可执行项目就是那个装着全部资源的主项目，拆成多个项目会把它搞坏。

正确做法是用一个多目标项目，改一下你的 `.csproj`：

```diff
-        <TargetFramework>net8.0-windows</TargetFramework>
+        <TargetFrameworks>net8.0;net8.0-ios;net8.0-android;net8.0-browser</TargetFrameworks>
```

其中 `net8.0` 为所有桌面平台所共用。

此外还要在 XPF SDK 中启用多目标支持：

```diff
+        <XpfSingleProject>true</XpfSingleProject>
```

:::caution
`net8.0-android`、`net8.0-ios` 和 `net8.0-browser` 这几个目标框架**只能加在可执行项目上**，不要加到共享库项目里。尤其是 `net8.0-browser`，它不支持非可执行项目，会引发 “Program does not contain a static 'Main' method suitable for an entry point.” 之类的构建错误。

库项目应当面向 `net8.0`。需要的话，库项目上也可以用 XPF SDK。若某个库要访问移动端原生 API，可以加上 `net8.0-android` 或 `net8.0-ios`，但不能加 `net8.0-browser`。
:::

## 定义入口点 {#defining-an-entry-point}

桌面 WPF 应用从 `Main` 方法起步，移动端和浏览器平台的入口机制则各不相同：Android 需要一个根 `Activity`，iOS 需要一个 `AppDelegate`，浏览器应用则由网页自己来启动。

为此，请在你的 `Application` 类中定义一个各平台都能调用的共享入口点：

```diff
    public partial class App : Application
    {
+        /// Shared App entry point.
+        public static int Start()
+        {
+            var app = new App();
+            app.InitializeComponent();
+
+            // Note, this method returns early on Mobile and Browser.
+            return app.Run();
+        }
    }
```

## Building

### .NET CLI

一次性构建所有平台：

```bash
dotnet build
```

只构建某个平台：

```bash
dotnet build -f net8.0-android
```

运行浏览器目标：

```bash
dotnet run -f net8.0-browser
```

:::note
.NET 官方并不支持直接从命令行运行 Android 或 iOS 应用，这两个目标请用 IDE。
:::

### Visual Studio

Visual Studio 默认面向桌面框架（`net8.0`）。要切到别的平台，请用目标框架下拉框：

![VS 目标选择器](/img/running-on-mobile-and-browser/vs-target-selector.png)

选中 Android 后，Visual Studio 会列出可选的模拟器或已连接的设备：

![VS Android 模拟器选择器](/img/running-on-mobile-and-browser/vs-android-emulators-selector.png)

若一个模拟器都看不到，请确认：
- Android SDK 已安装（可在 Visual Studio 安装程序的“单个组件”下安装）
- 至少配好了一个 Android 模拟器（打开**工具 > Android > Android 设备管理器**创建一个）
- Visual Studio 和 XPF SDK 都已更新到最新

### JetBrains Rider

Rider 的用法与 Visual Studio 类似，在运行配置下拉框中选择目标框架即可：

![Rider 目标选择器](/img/running-on-mobile-and-browser/rider-target-selector.png)

浏览器目标默认不显示。要加上它，请在下拉框中点 **Edit Configurations**，新增一个 “.NET Project” 配置并选好对应的目标框架，其余字段 Rider 会自动填好。

![Rider 添加浏览器目标](/img/running-on-mobile-and-browser/rider-adding-browser-target.png)

### VS Code

VS Code 需配合 [C# Dev Kit](https://marketplace.visualstudio.com/items?itemName=ms-dotnettools.csdevkit) 和 [.NET MAUI](https://marketplace.visualstudio.com/items?itemName=ms-dotnettools.dotnet-maui) 扩展来处理移动端目标。

:::note
Apple 不允许在非 macOS 机器上使用 iOS 模拟器或连接 iOS 设备。Apple 的移动端目标请在 macOS 上做，或者试试 [Visual Studio 的 macOS 配对功能](https://learn.microsoft.com/en-us/dotnet/maui/ios/pair-to-mac?view=net-maui-8.0)。
:::

## 发布 {#publishing}

发布请用 .NET CLI：

```bash
# Outputs an APK in /bin/Release/net8.0-android/publish/
dotnet publish -f net8.0-android

# Outputs an IPA in /bin/Release/net8.0-ios/publish/
dotnet publish -f net8.0-ios

# Outputs an app bundle in /bin/Release/net8.0-browser/browser-wasm/AppBundle/
dotnet publish -f net8.0-browser
```

:::caution
由于裁剪和 AOT 编译的缘故，以 Release 配置发布移动端和浏览器项目存在已知问题。请把发布产物仔细测一遍。
:::

## 已知限制 {#known-limitations}

与桌面相比，浏览器和移动平台天生就有一些约束。XPF 为其中一部分提供了兼容层，另一些则需要你改应用代码。

### Windowing

在移动端和浏览器目标上，XPF 通过嵌在平台单一视图（移动应用视图或网页内容）中的虚拟桌面来支持 `Window` 类，不需要额外写代码来启用。

虚拟窗口目前的限制：
- 尚不支持调整大小和拖动
- 不渲染窗口装饰
- 尚不支持从属窗口（但 `ShowDialog` 可用）

在移动端和浏览器上，请把主窗口最大化，让它铺满整个屏幕：

```csharp
public MainWindow()
{
    InitializeComponent();

    if (OperatingSystem.IsBrowser() || OperatingSystem.IsAndroid() || OperatingSystem.IsIOS())
    {
        WindowState = WindowState.Maximized;
    }
}
```

### DispatcherFrame

`DispatcherFrame` 及相关的 `Dispatcher` API 在所有移动端和浏览器平台上都不受支持。

### 同步对话框 API {#synchronous-dialog-apis}

WPF 的同步对话框 API（`Window.ShowDialog()`、`MessageBox.Show()`）在桌面上没问题，但移动端和浏览器上支持不了——这些平台不允许阻塞主线程。

请改用异步扩展方法：

**MessageBox:**
```diff
-var result = MessageBox.Show(parent, "Operation cannot be performed", "Title", MessageBoxButton.OK);
+var result = await MessageBoxEx.ShowAsync(parent, "Operation cannot be performed", "Title", MessageBoxButton.OK);
```

**ShowDialog:**
```diff
var dialog = new Window();
dialog.Owner = this;
-var result = dialog.ShowDialog();
+var result = await dialog.ShowDialogAsync();
```

这些扩展方法在桌面目标上同样可用，所以你大可处处用它们，图个一致。

:::note
文件对话框的异步扩展方法暂时还没有，但已在计划之中。若你在移动端或浏览器上急需这些或其他 API，请联系支持团队。
:::

### 文件系统访问 {#file-system-access}

移动端和浏览器应用都跑在沙箱里，没法按路径直接访问文件系统。

请把文件相关的 API 用法限制在文件选取器和基于流的接口上。若要在移动端访问可写的应用数据目录：

```csharp
var appDataPath = Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData);
```

:::note
浏览器应用除了用户主动发起的文件对话框之外，根本没有文件系统访问能力。
:::

### 浏览器中的线程 {#threading-in-the-browser}

浏览器环境的线程支持相当有限。请把它当成一个异步不是可选项、而是必选项的环境——网页应用的主线程阻塞不得。

若要启用最基本的线程支持（比如 `Task.Run` 或 `new Thread()`），请在项目文件中加上：

```xml
<PropertyGroup>
  <WasmEnableThreads>true</WasmEnableThreads>
</PropertyGroup>
```

### 平台专属代码 {#platform-specific-code}

若要从 XPF 项目中访问平台专属 API，做法与在 Avalonia 应用中一样。细节请见[平台专属 .NET](/docs/platform-specific-guides/dotnet)。
