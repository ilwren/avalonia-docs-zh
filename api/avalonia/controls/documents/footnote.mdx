<div className="apiref-page__lead">

A footnote as an element: the facade over a [Avalonia.Controls.Documents.TextModel.TextFootnote](xref:Avalonia.Controls.Documents.TextModel.TextFootnote) the way
[Avalonia.Controls.Documents.FlowDocument](xref:Avalonia.Controls.Documents.FlowDocument) is the facade over a [Avalonia.Controls.Documents.TextModel.TextDocument](xref:Avalonia.Controls.Documents.TextModel.TextDocument). The
text model owns the note ([Avalonia.Controls.Documents.TextModel.TextDocument.Footnotes](xref:Avalonia.Controls.Documents.TextModel.TextDocument.Footnotes)); the owning
document's [Avalonia.Controls.Documents.FlowDocument.Footnotes](xref:Avalonia.Controls.Documents.FlowDocument.Footnotes) materializes this element over it
on demand. Like any element, a note built from markup or code stays lazy: its
text document comes into being when the owner's document initializes or when the
note's content is first needed, and the model note when it joins the owner; until
then the owning document is its logical parent, as for a pending block.
[Avalonia.Controls.Documents.Footnote.NoteId](xref:Avalonia.Controls.Documents.Footnote.NoteId) pairs the note with the [Avalonia.Controls.Documents.RichFootnoteReference](xref:Avalonia.Controls.Documents.RichFootnoteReference)
anchor that carries the number; the rendered number is the note's position among
the document's notes, never stored here. Deleting the anchor removes the note in
the same undo unit; an emptied note survives until its anchor goes. It has its
own buffer, selection and caret; its undo joins the owner's stack; it never hosts
anchors, notes or bands of its own.
