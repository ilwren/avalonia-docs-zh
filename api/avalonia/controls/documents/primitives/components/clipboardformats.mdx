## 备注 {#remarks}

Format objects are cached as static singletons so that copy / paste hot
paths do not allocate new [Avalonia.Input.DataFormat&lt;T&gt;](xref:Avalonia.Input.DataFormat%601) instances per call.

Only the canonical platform identifier is published on copy. On paste,
alternative aliases are also probed where applicable (Linux ships both
`text/rtf` and `application/rtf`; macOS Word may use
`com.microsoft.rtf-compatible`).

### InProcessSnapshot 属性 {#inprocesssnapshot-property}

In-process-only format carrying a live [Avalonia.Controls.Documents.Serialization.Snapshot.DocumentSnapshot](xref:Avalonia.Controls.Documents.Serialization.Snapshot.DocumentSnapshot)
reference. Created via [Avalonia.Input.DataFormat.CreateInProcessFormat&lt;T&gt;(string)](xref:Avalonia.Input.DataFormat.CreateInProcessFormat%60%601%28System.String%29)
so the value never crosses the platform clipboard boundary — every
clipboard backend (Windows, X11, macOS, iOS, Browser) skips
[Avalonia.Input.DataFormatKind.InProcess](xref:Avalonia.Input.DataFormatKind.InProcess) entries when serializing to the
OS clipboard. Consumed via
[Avalonia.Input.Platform.IClipboard.TryGetInProcessDataAsync](xref:Avalonia.Input.Platform.IClipboard.TryGetInProcessDataAsync),
which returns the exact same [Avalonia.Input.IAsyncDataTransfer](xref:Avalonia.Input.IAsyncDataTransfer) instance
the producer published on the same process.

```csharp
public Avalonia.Input.DataFormat<Avalonia.Controls.Documents.Serialization.Snapshot.DocumentSnapshot> InProcessSnapshot { get; set; }
```

#### 备注 {#remarks-1}

Used by [Avalonia.Controls.Documents.Primitives.Components.ClipboardOperations](xref:Avalonia.Controls.Documents.Primitives.Components.ClipboardOperations) to ship the document snapshot
reference alongside RTF + plain text, providing a 100%-fidelity
fast path for same-process copy/paste that bypasses serialization
entirely. RTF/text remain on the clipboard as fallbacks for the
cross-process and cross-app cases.

### Rtf 属性 {#rtf-property}

Primary platform RTF format for the current OS:

- Windows: `Rich Text Format` (CF_RTF registered name)
- macOS: `public.rtf` (UTI)
- Linux: `text/rtf` (MIME)

```csharp
public Avalonia.Input.DataFormat<byte[]> Rtf { get; set; }
```

#### 备注 {#remarks-2}

Published as a [Avalonia.Input.DataFormat&lt;T&gt;](xref:Avalonia.Input.DataFormat%601) of [byte](xref:System.Byte) array,
not [string](xref:System.String). The Win32 clipboard backend writes
[Avalonia.Input.DataFormat&lt;T&gt;](xref:Avalonia.Input.DataFormat%601) string payloads as UTF-16 wide chars,
which Word and other RTF consumers cannot parse — they expect raw
7-bit ASCII bytes starting with `{\rtf1`. RTF is by spec ASCII
(non-ASCII characters use `\u` / `\'hh` escapes), so UTF-8
bytes are interchangeable with ASCII bytes here.
